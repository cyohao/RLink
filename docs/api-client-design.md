# 接口调用功能 · 第一期设计方案

## 1. 目标

在管理页面里增加一个「接口调用」标签页，作用类似 Postman：可以调用任意 HTTP 接口，包括对方的真实系统和本服务的模拟接口，并能把常用请求、环境变量保存下来反复使用。

**第一期包含**：编辑和发送请求、查看响应、环境变量、请求集合、历史记录、复制 curl、取消请求。

**第一期不包含**：粘贴 curl 导入、Postman 集合导入、multipart 文件上传、提取响应字段到变量、断言、把响应存为模拟接口、同时打开多个请求标签页、前置/后置脚本。

## 2. 总体架构

```
浏览器（接口调用页）                       mock-server                               目标接口
──────────────────                       ──────────────                          ──────────
编辑请求（含 {{变量}}）
   │ POST /__admin/api/client/send
   │ { request, variables }      ───▶    1. 替换变量
                                         2. 检查访问白名单
                                         3. 用 node:http / https 发出请求  ───▶  真实系统
                                            （处理重定向、解压、字符集、大小上限）  ◀───
   ◀───  { sent, response, timing }      4. 返回结果
展示响应，写入本机历史（localStorage）
   │ 用户点「保存到服务器」时
   │ POST /__admin/api/client/records  ───▶  写入 data/records.json
```

- 请求**一律由服务器转发**。这样没有跨域限制，可以设置任意请求头，能访问服务器所在内网的地址。
- 转发接口挂在 `/__admin/api/client/*` 下，沿用现有的 `ADMIN_TOKEN` 鉴权，并且**必须设置了 `ADMIN_TOKEN` 才能使用**（见第 7 节）。
- 不新增 npm 依赖，只用 Node 内置的 `http`、`https`、`zlib` 和 `TextDecoder`。
- **相对地址**（以 `/` 开头，比如 `/wms/api/task/out`）会自动发到本服务自己（`http://127.0.0.1:<当前端口>`），这样也能用来调模拟接口，调用同样会出现在「请求日志」里。
- 没写协议的地址（比如 `192.168.1.10:8080/api`）自动补上 `http://`。

### 3.1 左侧栏

- **集合**：只有一层分组，集合下面直接是请求。可以新建、重命名、删除集合，集合可以折叠。请求的右键或「⋯」菜单里有：复制、移动到其他集合、删除。
- **历史**：分为两个列表。
  - **本机历史**（默认）：保存在当前浏览器的 localStorage 里，各人只能看到自己的记录。最多 100 条，按时间倒序，每条显示「方法 + 地址 + 状态码 + 时间」。点开后把当时的请求载入编辑区，并显示当时的响应。可以清空。
  - **服务器记录**：在本机历史的某一条上点「保存到服务器」，这条记录就会存到服务器上，所有人都能看到，换浏览器、重启服务也不会丢，适合留作联调凭证。每条可以加一句备注，可以单独删除，最多保存 500 条。
  - 浏览器存储空间不够时，自动删掉最旧的本机历史；如果浏览器禁用了存储，本机历史只在当前页面有效，界面上会给出提示。
- 搜索框会同时按名称和地址过滤。

### 3.2 请求编辑区

| 区域 | 内容 |
|---|---|
| 请求行 | 方法（GET/POST/PUT/PATCH/DELETE/HEAD/OPTIONS）、地址、发送（请求过程中变成「取消」）、保存（下拉里有「另存为」「复制 curl」） |
| Params | 键 / 值 / 启用 三列的表格，和地址栏里的 `?a=1&b=2` **双向同步** |
| Headers | 键 / 值 / 启用 三列的表格。根据 Body 类型自动加的 Content-Type 用灰色显示「（自动）」，手动填写同名请求头时以手动填写的为准 |
| Body | 无 / JSON / 表单（x-www-form-urlencoded）/ 纯文本。JSON 类型复用现有的代码编辑框（Tab 缩进、格式化、格式检查）；表单类型是键值表格；纯文本可以自己选 Content-Type（text/plain、application/xml 等） |
| 设置 | 超时时间（默认 30 秒，最长 300 秒）、是否自动跟随重定向（默认是，最多 5 次）、是否忽略 HTTPS 证书错误（默认否） |

- 名称显示在编辑区标题上，可以直接点击修改。有未保存的修改时显示「●未保存」，切换请求前会确认是否放弃修改，和接口编辑页的行为一致。
- 快捷键：`Ctrl+Enter` 发送，`Ctrl+S` 保存。
- 新建的请求还没保存时，保存相当于「另存为」，需要选择放到哪个集合。

### 3.3 响应区

- 概要：状态码（2xx 绿色、4xx/5xx 红色）、总耗时、首字节耗时（鼠标悬停显示）、大小。
- **Body**：JSON 默认美化显示，可以切换成原始内容，可以一键复制。二进制内容（图片、文件等）只显示类型和大小。超过 10MB 的部分会被截断，并给出提示。
- **Headers**：响应头列表。
- **实际请求**：变量替换后真正发出去的方法、地址、请求头、请求体，用来排查「变量到底替换成了什么」。
- 请求失败（连不上、超时、证书错误等）时显示中文错误说明，比如「连接被拒绝：192.168.1.10:8080 没有服务在监听」。

### 3.4 环境管理（弹窗）

- 左边是环境列表，可以新建、重命名、删除、复制环境；右边是当前选中环境的变量表格（变量名 / 值 / 启用）。
- 顶部的环境下拉框可以选「无环境」。选中的环境保存在浏览器本地，每个人可以选自己的环境。
- 变量名只能用字母、数字、`_`、`-`，必须以字母或下划线开头，并且不能和内置函数重名（比如 `now`、`seq`），保存时会做检查。

### 3.5 与现有功能的衔接

- 接口编辑页的「调试」卡片保留，新增一个「在接口调用中打开」按钮，点击后跳到新标签页，并按当前接口预填好方法、路径和示例请求体（作为一个未保存的新请求）。
- 「导出配置 / 导入配置」会把集合和请求一起导出、导入。环境变量和历史记录不导出，详见第 6 节。

## 4. 变量与模板

- 写法和 Postman 一样，用 `{{变量名}}`，在地址、Params、Headers、表单字段、请求体里都可以用。
- 现有模板引擎（`src/template.js`）的**内置函数也可以直接用**：`{{now 'YYYYMMDD'}}`、`{{uuid}}`、`{{randomStr 6 'digit'}}`、`{{concat 'Bearer ' token}}` 等。
- 替换方式是**纯文本替换**：请求体中的 `"qty": {{qty}}` 会被替换成 `"qty": 10`，`"t": "{{timestamp}}"` 的结果仍然是字符串。这和 Postman 的行为一致，所以不会像模拟接口的返回值那样保留原始类型。`$repeat` 在请求体里不生效。
- **未定义的变量会阻止发送**：发送前检查所有简单形式的 `{{xxx}}`，只要不是内置函数、在当前环境里又没有启用这个变量，就直接报错「变量 token 未定义（当前环境：测试环境）」，避免把空的 token 发出去。编辑区也会实时给出提示。函数参数里用到的变量（比如 `{{concat 'Bearer ' token}}` 里的 `token`）不在检查范围内，找不到时按空字符串处理。
- 注意：`seq` 的计数器和模拟接口是共用的。

`template.js` 需要做的改动：新增并导出 `renderText(s, ctx)`，只做文本替换，不保留原始类型。现有函数的行为不变。

## 5. 后端设计

### 5.1 新增文件

| 文件 | 作用 |
|---|---|
| `src/httpClient.js` | `sendRequest(opts)`：基于 `http`/`https` 发请求，处理超时、重定向、gzip/deflate/br 解压、字符集解码（支持 GBK）、10MB 大小上限、取消请求，并计时 |
| `src/clientStore.js` | `ClientStore`：集合、请求、环境的读写（文件 `data/client.json`），以及服务器记录（文件 `data/records.json`）。写入方式和 `Store` 一样，先写临时文件再改名 |
| `src/clientRouter.js` | `/client/*` 管理接口：替换变量、检查白名单、调用 `httpClient`、管理服务器记录 |

`src/app.js` 在管理路由完成鉴权之后挂载 `router.use('/client', createClientRouter(...))`；`src/index.js` 负责创建 `ClientStore` 并传进去。

### 5.2 数据格式

`data/client.json`：

```jsonc
{
  "version": 1,
  "collections": [
    { "id": "c1a2b3", "name": "昆船 WMS", "order": 0 }
  ],
  "requests": [
    {
      "id": "r9f8e7",
      "collectionId": "c1a2b3",
      "name": "出库任务下发",
      "order": 0,
      "method": "POST",
      "url": "{{baseUrl}}/wms/api/task/out",
      "params":  [{ "key": "debug", "value": "1", "enabled": false }],
      "headers": [{ "key": "X-Auth-Token", "value": "{{token}}", "enabled": true }],
      "body": {
        "mode": "json",                  // none | json | form | raw
        "json": "{\n  \"taskNo\": \"{{uuid}}\"\n}",
        "form": [],                      // [{ key, value, enabled }]
        "raw": "",
        "rawType": "text/plain"
      },
      "options": { "timeout": 30000, "followRedirects": true, "insecure": false },
      "createdAt": "2026-10-27T08:00:00.000Z",
      "updatedAt": "2026-10-27T08:00:00.000Z"
    }
  ],
  "environments": [
    {
      "id": "e5d4c3",
      "name": "测试环境",
      "vars": [
        { "key": "baseUrl", "value": "http://192.168.1.10:8080", "enabled": true },
        { "key": "token",   "value": "abc123",                   "enabled": true }
      ]
    }
  ]
}
```

- 请求单独放在一个扁平数组里，通过 `collectionId` 关联集合。移动请求只需要改这个字段。
- Params 用表格保存，地址栏里只保留 `?` 之前的部分。前端负责两边的同步：解析地址栏时把 query 拆到表格里，发送时再拼回去。

**历史记录的结构**：本机历史（localStorage 键 `mockClientHistory`）和服务器记录（`data/records.json`，最多 500 条）用同一种结构，每条包含：

```jsonc
{
  "id": "h1", "time": "...",
  "note": "",                     // 仅服务器记录有，备注
  "request": { /* 和上面的请求结构相同，是替换变量之前的快照 */ },
  "envName": "测试环境",
  "sent": { "method": "POST", "url": "http://192.168.1.10:8080/wms/api/task/out", "headers": {}, "body": "..." },
  "response": { "status": 200, "statusText": "OK", "headers": {}, "body": "...", "size": 1234, "truncated": false },
  "error": null,                   // 失败时为 { "code": "ECONNREFUSED", "message": "连接被拒绝…" }
  "timing": { "totalMs": 128, "ttfbMs": 90 }
}
```

请求体和响应体各自截断到 20KB，和请求日志一致。这样 100 条本机历史最多占用约 4MB，在浏览器 localStorage 的常见上限（约 5MB）之内，服务器记录文件也不会太大。

### 5.3 接口列表（都在 `/__admin/api/client` 下面）

| 方法与路径 | 说明 |
|---|---|
| `GET /` | 一次性返回 `{ collections, requests, environments, proxy: { allowHosts } }`，数据量小，不分页 |
| `POST /collections` · `PUT /collections/:id` · `DELETE /collections/:id` | 集合的增、改、删。删除集合时会同时删除其中的请求 |
| `POST /requests` · `PUT /requests/:id` · `DELETE /requests/:id` | 请求的增、改、删。移动请求就是 PUT 时改 `collectionId` |
| `PUT /environments` | 一次性保存全部环境（弹窗点保存时提交整个列表） |
| `POST /send` | 发送请求，请求体为 `{ request, variables, envName }`，详见 5.4 |
| `GET /records` · `GET /records/:id` | 服务器记录列表（只返回概要，不含请求体和响应体）、单条详情 |
| `POST /records` · `PUT /records/:id` · `DELETE /records/:id` | 把一条本机历史保存到服务器、修改备注、删除 |

`/send` 由前端直接传入变量（`variables`），而不是只传环境 id。这样环境里还没保存的修改也能立刻生效，服务器端不需要保存状态。

### 5.4 `/send` 处理流程

1. 校验请求结构，并按 `store.js` 的方式规范化。
2. 检查有没有未定义的变量（见第 4 节），有就返回 400 和对应的错误说明。
3. 替换变量，拼出最终的 URL：处理相对地址和缺少协议的情况，再拼上启用的 Params。
4. 生成请求头：启用的 Headers；根据 Body 类型补上 Content-Type（`application/json`、`application/x-www-form-urlencoded`，或纯文本时选的类型）；没有填 `User-Agent` 时用 `RuiLink/1.0`。
5. 检查访问白名单（见第 7 节）。重定向之后的每一跳也要检查。
6. 调用 `sendRequest`。浏览器断开连接（用户点了「取消」）时同时中止发往目标的请求。
7. 返回结果（服务器不保存，由前端写入本机历史）：

```jsonc
// 成功（HTTP 200）
{ "sent": {...}, "response": {...}, "timing": {...}, "redirects": ["http://..."] }
// 发送失败也返回 HTTP 200，结果里带 error，前端统一展示
{ "sent": {...}, "error": { "code": "ETIMEDOUT", "message": "请求超时（30 秒内没有响应）" }, "timing": {...} }
```

只有参数本身有问题（结构不对、变量未定义、地址不在白名单里）才返回 4xx。

### 5.5 `httpClient` 细节

- 发送前计算 `Content-Length`。GET/HEAD 请求如果填了请求体会被忽略，前端会给出提示。
- 响应解压支持 `gzip`、`deflate`、`br`；请求头里默认加上 `Accept-Encoding: gzip, deflate, br`，用户手动填写时以用户为准。
- 字符集：从 `Content-Type` 的 `charset` 读取，用 `TextDecoder` 解码，支持 GBK/GB18030；无法识别时按 UTF-8 解码。
- 判断是否为文本：`text/*`、`*json*`、`*xml*`、`*javascript*`、`x-www-form-urlencoded`，或者没有 Content-Type 但内容可以按 UTF-8 正常解码。其他情况都按二进制处理，只返回大小。
- 响应超过 10MB 时停止读取，并设置 `truncated: true`。
- 重定向：301/302/303 改为 GET 并去掉请求体；307/308 保持原来的方法和请求体；跨域名跳转时去掉 `Authorization` 和 `Cookie`。
- 常见错误码对应的中文说明：`ECONNREFUSED`、`ENOTFOUND`、`ETIMEDOUT`、`ECONNRESET`、`EHOSTUNREACH`、各类证书错误（会提示可以在「设置」里开启忽略证书错误）。

## 6. 导出与导入

- 导出文件升级为 `version: 2`，在原来的 `mocks` 之外增加 `client: { collections, requests }`。**不导出环境变量**（里面可能有 token），也不导出历史和服务器记录。
- 导入时兼容 `version: 1` 的文件（只包含 mocks）。导入弹窗里会分别显示「接口 N 个，集合 N 个，请求 N 个」。
- 合并导入：集合和请求按 id 覆盖，其他的保留。覆盖导入：清空接口、集合、请求之后再导入。**两种方式都不会动现有的环境变量**。
- 迁移到另一台服务器后，环境变量需要在新服务器上重新配置。请求里用到但新服务器上还没有的变量，发送时会报「未定义」。

## 7. 安全

转发功能等于让服务器替能登录管理页的人去访问内网的任意地址，所以：

**必须设置 `ADMIN_TOKEN` 才能使用。** 没有设置时：
- 「接口调用」标签页仍然显示，但页面上只有一条提示：「接口调用功能需要先设置管理口令 ADMIN_TOKEN，设置方法见 README」；
- `/__admin/api/client/*` 全部返回 403；
- 启动日志里会给出相同的提示。

此外还有两个可选的控制：

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `CLIENT_ENABLED` | `true` | 设为 `false` 时即使设置了口令也关闭接口调用功能：标签页隐藏，`/client/*` 返回 403 |
| `PROXY_ALLOW_HOSTS` | 空（不限制） | 逗号分隔的白名单，支持 `host`、`host:port`、`*.example.com`、`192.168.1.*`。比如 `192.168.10.*,wms.internal:8080`。不在名单里的地址会被拒绝 |

另外，发往本服务自身的相对地址请求不受白名单限制。

`.env.example` 和 `docker-compose.yml` 里会加上 `PROXY_ALLOW_HOSTS`、`CLIENT_ENABLED` 的示例和说明。

## 8. 前端实现

- 新增 `public/client.js`，在 `index.html` 里放在 `app.js` 后面加载，复用 `app.js` 里的 `h`、`api`、`toast`、`copyText`、`prettyText`、`codeArea` 等全局函数。`app.js` 的改动只有三处：注册新标签页、在调试卡片上加按钮、导出导入时带上 client 数据。
- 状态保存在 `clientState`：当前请求的草稿、是否有未保存修改、选中的环境 id（存在 localStorage）、本机历史（存在 localStorage）、正在进行的请求（`AbortController`）。
- 所有 localStorage 的读写都用 try/catch 包起来，沿用现有的 `storageGet` / `storageSet`。写入时空间不够，就删掉最旧的一半记录再重试。
- 新增的样式放在 `style.css` 末尾，沿用现有的变量和组件样式（`.card`、`.btn`、`.sub-table` 等）。

## 9. 测试

新增 `test/client.test.js`，在测试里起一个本地的目标服务器来验证：

- 变量替换、内置函数、未定义变量报错；
- 拼接 Params、相对地址指向本服务的模拟接口；
- 三种 Body 类型和自动补 Content-Type；
- 超时、连接被拒绝、重定向（303 改为 GET、307 保留请求体、跨域名去掉 Authorization）；
- gzip 解压、GBK 解码、超过大小上限时截断；
- 白名单拦截（包括重定向之后的地址）、`CLIENT_ENABLED=false`；
- 集合和请求的增删改、删除集合时同时删除请求；服务器记录的增删、改备注，最多 500 条；
- 导出导入 v2 格式（不含环境变量，导入不影响现有环境）、兼容 v1；
- 没设置 `ADMIN_TOKEN` 时 `/client/*` 返回 403；设置了口令但没带口令时返回 401。

## 10. 工作量和顺序

1. 后端：`httpClient`、`template.renderText`、`clientStore`、`clientRouter`，以及对应的测试 —— 约 1 天
2. 前端：请求编辑区、响应区、发送和取消 —— 约 0.5–1 天
3. 前端：集合、历史、环境弹窗、调试卡片衔接、导出导入 —— 约 0.5–1 天
4. README 和「使用说明」页更新、整体自测 —— 约 0.5 天

## 11. 已确认的决定

| 问题 | 结论 |
|---|---|
| 安全默认值 | 必须设置 `ADMIN_TOKEN` 才能使用接口调用功能 |
| 历史记录 | 默认保存在各自的浏览器里；单条记录可以点「保存到服务器」，保存后所有人都能看到 |
| 集合层级 | 一层 |
| 导出 | 不包含环境变量 |

## 12. 实现说明（与上文的差异）

- 环境选择框和「管理」按钮放在左侧栏顶部，不在编辑区右上角，这样没打开请求时也能切换环境。
- 左侧栏是三个标签：集合 / 历史 / 服务器记录。在「历史」里点某一条右侧的 ☁ 就能保存到服务器。
- 「复制 curl」通过 `POST /client/preview` 由服务器替换变量后生成，所以复制出来的内容和实际发送的一致；但每次调用 `{{uuid}}`、`{{seq}}` 这类函数都会得到新值。地址是相对路径时，curl 里用的是浏览器当前访问的地址。
- 「另存为」和「复制 curl」直接放在编辑区顶栏，没有做成下拉菜单。
