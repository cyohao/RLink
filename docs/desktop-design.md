# 桌面端 · 设计方案（Tauri + Rust 重写服务）

## 1. 目标

做一个 Windows 桌面应用，包含网页版的全部功能：模拟接口、请求日志、接口调用。

- **可以离线使用**：本机运行一份完整的模拟服务，数据存在本机。
- **也能连接服务器**：读写服务器上的共享数据，但「接口调用」从本机发出，能访问本机和所在局域网。
- 只支持 Windows，手动分发，不做自动更新和代码签名。
- 以实现速度为第一目标，不考虑长期维护。服务器上的 Docker 部署继续用现有的 Node 版本。

## 2. 总体架构

```
┌──────────────────────── 瑞联.exe（一个文件） ────────────────────────┐
│                                                                            │
│  Tauri 窗口（WebView2）                                                     │
│     打开 http://127.0.0.1:<端口>/__admin/      ← 页面就是现在的 public/       │
│                    │                                                       │
│                    ▼                                                       │
│  内置服务（Rust：axum + tokio），监听 127.0.0.1（可选 0.0.0.0）              │
│     /__admin/          管理页面静态文件（编译时打包进 exe）                  │
│     /__admin/api/*     管理接口 ── 本地工作区：读写本机数据                  │
│                                └─ 连接服务器：转发到远端服务器（发送请求除外） │
│     /__health                                                              │
│     其他路径            模拟接口                                            │
│     /__admin/api/client/send   用 reqwest 从本机发出请求                     │
│                                                                            │
│  数据目录：%APPDATA%\com.huarui.ruilink\  （mocks.json、client.json、     │
│            records.json、settings.json）                                    │
└────────────────────────────────────────────────────────────────────────────┘
```

**核心原则：Rust 版服务和 Node 版服务的 HTTP 接口、数据文件格式完全一致。**

- 前端页面不用重写，网页版和桌面版共用 `public/`。
- 本机数据目录里的文件可以和服务器上的直接互相拷贝；导出、导入的文件两边通用。
- 「连接服务器」模式只需原样转发管理接口。

## 3. 两种工作区

| | 本地工作区（默认） | 连接服务器 |
|---|---|---|
| 模拟接口配置、集合、环境、服务器记录 | 本机数据目录 | 远端服务器（转发管理接口） |
| 请求日志 | 本机内置服务收到的调用 | 远端服务器的日志 |
| 模拟接口由谁提供 | 本机：`http://127.0.0.1:端口/...` | 远端服务器 |
| 「接口调用」从哪里发出 | 本机 | **本机**（`/client/send`、`/client/preview` 不转发） |
| 断网时 | 可用 | 不可用 |

- 相对地址（`/wms/...`）在本地工作区指本机服务，在连接服务器模式下指远端服务器。
- 两种工作区之间不自动同步，用现有的「导出配置 / 导入配置」手动同步。
- 切换工作区不用重启应用：内置服务里有一个「当前模式」状态，切换后页面重新加载。

## 4. 口令与安全

- 内置服务启动时生成一个随机口令，作为本机的 `ADMIN_TOKEN`。
- 窗口加载页面前，用 Tauri 的初始化脚本把口令写进页面的 localStorage（键 `mockAdminToken`，和现在网页版一致），用户无感。
- 默认只监听 `127.0.0.1`，外部访问不到。打开「允许局域网访问」后改为监听 `0.0.0.0`：局域网里的其他设备能调本机的模拟接口；管理接口仍需口令，口令在设置页显示，可以复制。
- 连接服务器时，远端口令保存在 `settings.json`。用 Windows DPAPI 加密是可选项，为了速度第一版先明文保存，在设置页注明。

## 5. 设置（页面上新增「桌面设置」标签）

只在桌面端显示：`/__admin/api/info` 返回 `desktop` 字段，前端据此决定是否显示。

| 设置 | 说明 | 生效方式 |
|---|---|---|
| 工作区 | 本地 / 连接服务器（地址 + 口令，可以「测试连接」） | 立即生效，页面自动刷新 |
| 端口 | 默认 3000；被占用时自动换一个空闲端口，并提示 | 重启应用 |
| 允许局域网访问 | 监听 0.0.0.0，显示本机口令和局域网地址 | 重启应用 |
| 数据目录 | 显示路径，按钮「打开所在文件夹」 | — |

设置保存在数据目录的 `settings.json`。

## 6. Rust 实现：模块对照

代码放在 `desktop/src-tauri/`，单个 crate：

| Node 文件 | Rust 模块 | 用到的库 |
|---|---|---|
| `template.js` | `template.rs`：词法分析、语法解析、内置函数、`$repeat`、`renderText` | serde_json（打开 `preserve_order`，保证 JSON 字段顺序不变） |
| `engine.js` | `engine.rs`：路由匹配和打分、参数校验、条件场景 | — |
| `store.js` | `store.rs`：模拟接口配置的规范化、增删改、导入、原子写文件 | serde |
| `clientStore.js` | `client_store.rs`：集合、请求、环境、服务器记录 | serde |
| `httpClient.js` | `http_client.rs`：超时、重定向（手动循环处理）、解压、字符集、10MB 上限、取消、中文错误说明 | reqwest（gzip、brotli、deflate，rustls）、encoding_rs |
| `clientRouter.js` | `client_router.rs`：变量替换、组装请求、访问白名单 | — |
| `app.js` | `server.rs`：管理接口、请求日志、模拟接口处理、跨域、静态文件 | axum、tower-http、include_dir |
| — | `upstream.rs`：连接服务器模式下转发管理接口 | reqwest |
| — | `desktop.rs`：设置、端口选择、窗口、口令注入、只允许运行一个实例 | tauri 2、tauri-plugin-single-instance |

### 需要特别对齐的行为

- **JSON 字段顺序**：返回值模板渲染后，字段顺序要和配置里写的一致，所以打开 `preserve_order`。
- **数字格式**：JS 里整数显示为 `3`，不是 `3.0`。计算结果是整数时按整数输出。
- **查询参数**：Express 会把 `a=1&a=2` 解析成数组、`a[b]=1` 解析成嵌套对象。Rust 版支持同名参数解析成数组和单层 `a[b]`，更复杂的写法不支持。
- **请求体**：所有类型都先按文本读取，上限 10MB；然后和 Node 版一样，依次尝试表单格式、JSON，都不是就当纯文本。
- **请求头名称**：一律转成小写，和 Node 版一致，所以模板里 `{{headers.x-token}}` 的写法不变。
- **`seq` 计数和请求日志**：只保存在内存里，和 Node 版一样。

## 7. 前端改动（很少）

- `/info` 返回 `desktop: { workspace, remoteUrl, ... }` 时：
  - 顶栏显示当前工作区（「本地」或「服务器：192.168.x.x」）；
  - 显示「桌面设置」标签页。
- 新增 `public/desktop.js`：设置页面的代码，只在桌面端加载。
- 网页版的行为完全不变。

## 8. 测试

- **Rust 单元测试**：照搬 `test/template.test.js` 中的用例，以及路由匹配、参数校验的用例。
- **对照测试**：新增 `test/compat.test.js`，只通过 HTTP 调用，不依赖服务的内部代码。设置环境变量 `MOCK_BASE_URL` 后，它可以测试任何一个正在运行的服务。用它分别测试 Node 版和 Rust 版，**两边结果都通过才算对齐**。内容涵盖现有的 I-01 到 I-04 接口用例、管理接口、导入导出、接口调用（重定向、gzip、GBK、超时、白名单）。
- **桌面端**：手动测试，包括启动、端口被占用时自动换端口、切换工作区、允许局域网访问、离线使用。

## 9. 打包

- 本机访问不了 GitHub，Tauri 打安装包需要的 NSIS、WiX 下载不了。所以**只输出单文件 exe**（`tauri build --no-bundle`），页面文件编译进 exe。
- Win10/11 自带 WebView2，双击就能运行。没有代码签名，首次运行时 Windows 可能提示，选「仍要运行」。
- 以后需要安装包时，可以把 NSIS 手动放到 Tauri 的工具目录再打包。

## 10. 不做的事

自动更新、代码签名、两个工作区之间自动同步、macOS 和 Linux、Docker 部署改用 Rust 版。

## 11. 工作量和顺序

1. Rust 模板引擎和规则引擎，加单元测试 —— 约 0.5 天
2. 数据存储、管理接口、模拟接口处理，用对照测试和 Node 版对齐 —— 约 1 天
3. 接口调用（HTTP 客户端、变量替换、白名单、服务器记录），用对照测试对齐 —— 约 1 天
4. Tauri 外壳、设置、连接服务器模式、前端改动 —— 约 1 天
5. 打包、整体测试 —— 约 0.5 天

合计约 4 天。

## 12. 实现说明（与上文的差异）

- 本机访问 crates.io 很慢，`desktop/src-tauri/.cargo/config.toml` 里改用 rsproxy.cn 镜像，只对这个项目生效。
- 设置了环境变量 `HUARUI_DEVTOOLS_PORT` 时，会打开 WebView2 的远程调试端口，用于自动化测试；正常使用时不生效。
- `ruilink.exe --serve --port 3000 --data-dir 目录 --token 口令` 可以不开窗口只运行服务（对照测试就是这样启动的）。发布版没有命令行窗口，看不到输出，调试时用 `cargo build` 出的调试版。
- 「桌面设置」里修改端口或局域网访问后，需要手动关闭应用再打开，没有做自动重启（和「只允许运行一个实例」的机制容易冲突）。
- 连接服务器时，服务器口令错误会返回 502 和明确提示，而不是 401，避免页面误以为本机口令错误而弹出输入框。
- 接口调用中「取消」请求时，浏览器那边会立即显示已取消，但本机发往目标的请求不一定马上中止，最晚在超时后结束。
